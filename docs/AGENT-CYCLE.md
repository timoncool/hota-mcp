# Цикл работы агента: игра → пробел → инструмент → проверка → запись

Этот документ описывает, как вести проект дальше без «затупов»: каждый ход игры одновременно двигает партию и покрытие MCP.

## Алгоритм хода

1. **Наблюдение.** `observe` (или `debug_snapshot`, если нужен кадр для человека). Проверить `screen`, `revision`, `player`, `date`, `hero`, `towns`, `resources`, `Actions`. Неизвестный экран = нет покрытия адаптера, а не повод угадывать ввод.
2. **Выбор цели.** Из `Actions` и `nearby_targets` выбрать одно короткое намерение (собрать, открыть город, купить, ударить, ответить на диалог). Приоритет — то, что нужно партии сейчас (движение, армия, доход), а не то, что проще проверить.
3. **Действие.** Уникальный `operationId`, текущий `revision`, семантический ключ. Не выдумывать ключи, которых нет в `Actions`.
4. **Проверка результата.** Новое `observe`: смена `revision` плюс предметное подтверждение (позиция/ресурсы/гарнизон/лог боя/запись журнала). `uncertain` — не повторять с новым ID: сначала состояние и журнал.
5. **Пробел.** Если шаг 2-4 упёрся в отсутствие функции (нет действия, нет чтения, экран не распознан, «выберите героя сначала») — это **задача на инструмент**, а не повод импровизировать. Записать пробел в `CAPABILITIES.md` со статусом `missing` и описанием, чем он помешал.
6. **Инструмент.** Реализовать минимально достаточную функцию в мосте: чтение структуры в `GameReader`/`*Reader`, действие в `Actions` + маппинг в `Bridge.Click`, при необходимости нативная операция. Кнопки диалогов — адресным оконным событием по границам контрола (см. `playbooks/save-load-cycle.md`).
7. **Проверка инструмента в игре.** Тот же шаг, который раньше не проходил, должен пройти; зафиксировать «до/после» (значения полей), снимок по запросу человека.
8. **Запись.** Обновить: `CAPABILITIES.md` (статус + свидетельство), `skills/hota-player/SKILL.md` (новый проверенный flow), при необходимости playbook, `STATE.md` (контрольная точка), `TASKS.md` (задача закрыта/открыта). Коммит с чистым сообщением, пуш в репозиторий.

## Правила, которые уже оплачены ошибками

- Кнопки: адресное оконное событие по границам контрола. Подмена vtable ломает загрузку (крах карты) и «главное меню».
- Вопросы: не Enter/Escape, а адресное событие по `iokay.def`/`icancel.def`.
- Загрузка проверяется различимым состоянием (дата/ресурсы/герой), а не «экран сменился».
- `move_to`: `uncertain` без движения и без смены даты = цель недостижима; не ретраить вслепую.
- Не подтверждать непрочитанное: имя сейва, текст вопроса, выбранный гарнизон.
- Не перезаписывать `111ы.GM1`/`111.GM1`; автосейв игры трогать не нужно.
- Никаких кликов «по картинке»: координаты считает адаптер из структур UI/карты.

## Ритм

- Один цикл = один осмысленный шаг игры + при необходимости один инструмент. Не смешивать несколько крупных изменений без проверки.
- После каждого цикла — короткий отчёт человеку: что сделано в партии, какой пробел найден, что реализовано, что проверено.
- Прогресс партии важнее числа инструментов: инструмент без применения в партии не считается покрытием.

## Отчёт за игровой день (правило человека, 20.09.2026)

- Каждый игровой день закрывается отчётом человеку: что сделано в партии + какие инструменты появились/проверены + что нового в карте слоя игры + пробелы дня + доказательства.
- Отчёт публикуется в чат и дописывается в `docs/DAILY-REPORT.md` по шаблону из этого файла.
- Игра ведётся ради картографирования слоя (экраны, элементы, id/ассеты, структуры, переходы), а не ради самой игры: день без записи в карту считается потерянным.

## Скриншоты (правило человека, 20.09.2026)

- `debug_snapshot`/кадры — временный костыль для прокладки путей и ориентации, пока адаптер не покрыл экран. Разрешён только на этапе разработки.
- Боевая игра агента — без скриншотов: только структуры (наблюдение, действия, границы контролов, тайлы карты). Кадр не является доказательством действия и не заменяет предметную проверку.
- Если без кадра экран не понимается — это пробел покрытия адаптера, задача на инструмент, а не путь «смотреть глазами».

## Ближайшие задачи (порядок)

1. `hero:select` — выбор своего героя на карте (сейчас после выхода из города наблюдение героя пустое, `nearby` отвечает «Select a hero first»).
2. Чтение карточки героя: первичные навыки, уровень, опыт, артефакты, навыки (в наблюдении они пока пустые).
3. Передача армии между героем и гарнизоном, выбор количества найма (кроме «максимум»).
4. Диалоги наград и выбора (сундук «золото/опыт», повышение уровня, новые заклинания, артефакты).
5. Полная карточка существа/заклинания штатным осмотром.
6. Бой: стрельба, площадные и массовые заклинания, книжка по страницам, отступление.
7. Главное меню: подтверждение выхода (дефект с `iokay`), заставка/intro, «Начать заново».
8. Настройки новой партии: сложность, цвета, команды, герои, бонусы, таймер; полный выбор в случайной карте.
9. Сохранение: ввод и чтение имени, перезапись, обработка сообщений.
