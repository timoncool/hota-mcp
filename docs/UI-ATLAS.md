# План картографирования интерфейса

## Рабочий цикл

1. Выбрать один экран и конкретный пользовательский переход из очереди ниже.
2. Одним вызовом MCP debug_snapshot сохранить observe, PNG и парный JSON с проверкой неизменной revision. Сверить видимые надписи, выбранные значения, доступность контролов и игровые ограничения. Непрочитанное поле записать как пробел.
3. Подключить семантическое действие через штатный обработчик. Сохранить запрос, результат и повтор с тем же operation ID.
4. Снять новое observe и кадр; проверить ожидаемый экран/значение и отсутствие незапланированных изменений. Не считать возврат обработчика доказательством результата.
5. Сохранить воспроизводимый JSON flow в tests/flows. Автоматическая и визуальная проверки имеют отдельные статусы.
6. После проверки добавить переход и ограничения в skill, обновить очередь и контрольную точку; перейти к следующему экрану.

## Стенд

`dotnet run --project tests/HotaMcp.Smoke -- . --atlas tests/flows/random-setup.json --state-dir "$env:LOCALAPPDATA\HotaMcp"`

Официальный MCP-клиент выполняет рецепт, сохраняет в build/atlas уникальную папку: статус сервера, список инструментов, рецепт, JSON до/после, запросы/результаты, PNG и REPORT.md. При ошибке сохраняет её и останавливает последовательность. Никакого OCR, CUA, активации окна или системного ввода. Скриншоты только для разработческой сверки; они не отправляются модели автоматически. Человеческую визуальную проверку стенд сам себе не выставляет.

## Очередь покрытия

Проверенный прогон: build/atlas/20260919-175423-e6ce45, семь шагов random-setup.json прошли автоматические проверки. Статус визуальной сверки каждого шага пока pending. Нельзя выдавать автоматический PASS за визуальную верификацию.

Все диалоги должны читаться программно: текст, варианты, доступность, результат. Кадры нужны только разработчику для сверки. Проверены linked-list элементы сюжетного диалога 0x63db40, подтверждение конца хода и новое сообщение на следующий день.

| Этап | Поля и переходы | Приёмка |
| --- | --- | --- |
| 1. Подготовка | Главное меню → новая игра → режим; список сценариев; генератор; участники | Переключение вкладок, подписи, отсутствие игровых данных до старта |
| 2. Генератор | Размер/уровни, игроки, ИИ, вода, монстры, дороги, шаблон, команды | Текущее/доступное/заблокированное; изменение и возврат каждого поля |
| 3. Сценарий | Каталог/фильтры/прокрутка, выбранная карта, описание, победа/поражение | Выбор по ID без анализа скрытого содержимого карты |
| 4. Участники | Сложность, цвета/имена, города/герои/бонусы, таймеры, опции | Согласованная конфигурация; чтение зависимых ограничений |
| 5. Старт и сохранение | Начать, стартовые диалоги, сохранить/загрузить | Подтверждённая партия и точка восстановления |
| 6. Город | Войти/выйти, стройка, найм/улучшение, герои/армии | Одна транзакция каждого типа; штатная цена; устойчивый возврат |
| 7. Приключение | Движение, сбор/посещение/захват, герои, конец хода | Состояние и расход движения; честная видимость |
| 8. Бой | Активный стек, цели, движение/атака/стрельба, магия, ожидание/защита | Полный бой и возврат; потери и награды |
| 9. Полная карта | Ходы, недели, события, победа/поражение | Прохождение основным агентом; затем DeepSeek |
| 10. Остальные режимы | Hotseat, союзы, LAN, передача человеку, восстановление | Разделение сторон и полный жизненный цикл |

Первый проход закрывает один полный путь до игры и победы. Расширение на все города/фракции проводится после этого, не задерживая первую сквозную партию.
