# Интеграция в существующий HD Launcher

Проверено 19.09.2026 на установленной игре. Требование пользователя — вкладка MCP внутри существующего лаунчера, а не ещё один самостоятельный интерфейс запуска.

## Установленные факты

- Каталог: `G:\HoMM 3 Complete`.
- Работающий процесс: `HD_Launcher.exe`, аргументы `"h3hota.exe" <#hota15>`.
- Заголовок окна: `HoMM3 HD 5.8 R18 Launcher`.
- Главное окно — Win32 dialog (`#32770`); вкладки — `SysTabControl32`, control ID 1046. Кнопка «Играть» имеет ID 1007, «Выход» — 1002.
- `HD_Launcher.exe`, `HD_LauncherNative.dll` и `HotA_launcher.exe` — PE x86 (Machine 0x14C), без CLR header. Это не .NET-приложения.
- В EXE есть ссылка на `HD_LauncherNative.dll`; назначение внутренних функций этой DLL ещё требует исследования.
- `_HD3_Data/HD_Launcher.ini`: `<CloseAfterLaunch> = 0`; работа после запуска игры соответствует предложенному жизненному циклу MCP.
- Настройки игры находятся в `_HD3_Data/Settings/hota.ini`; текущая внутренняя графическая поверхность — 1816×757. Запись настроек при исследовании не выполнялась.
- В дереве контролов есть скрытая группа «Плагины», но наличие этой группы не доказывает API расширения самого лаунчера и поддержку произвольного плагина для HotA.

Инвентаризация выполнена чтением файлов и Win32 EnumWindows/EnumChildWindows/GetClassName/GetWindowText. Картинки/OCR, изменение файлов игры и внедрение модулей не использовались.

## Проверка исходников и аналогов

- [Официальное описание HD Mod](https://sites.google.com/site/heroes3hd/eng/description).
- [H3Landscape](https://github.com/Paracelsus83/H3Landscape) показывает установку игрового HD-плагина через лаунчер. Это не доказательство возможности добавить вкладку в интерфейс лаунчера.
- [HeroesLauncher/heroeslauncher](https://github.com/HeroesLauncher/heroeslauncher) найден в поиске, но корневое дерево проверенного репозитория содержит только `.github`, `LICENSE`, `README.md`. Готовой исходной базы для модификации установленного HD Launcher он не предоставляет.

В рамках проверки исходники и документированный API расширения HD Launcher не найдены. Это не утверждение, что их нигде не существует.

## Предлагаемая граница компонентов

Нативный x86-модуль интеграции отвечает только за вкладку, её сообщения, кнопки и жизненный цикл. Изоляция игрового адаптера и MCP от UI позволяет сбою расширения не превращать лаунчер в зависший сервер. Язык основного сервиса окончательно выбирается по требованиям; Python исключён пользователем. C#/.NET остаётся кандидатом самостоятельного сервиса, но не готовым решением для загрузки в этот нативный EXE.

Вкладка: состояние сервера и игры, автозапуск, запуск/остановка MCP, копирование конфигурации подключения, список подключённых агентов и их сторон, пауза/передача управления, краткий журнал. Стратегии выбирает агент, вкладка управляет подключениями и выполнением.

Жизненный цикл: при открытии лаунчера запуск по настройке; при закрытии блокировка новых команд и безопасное завершение сервера, без закрытия игры. Скрытие/сворачивание окна не равно завершению процесса. Учитывать существующий флажок «Закрывать после запуска игры», не менять его незаметно.

Несколько harness должны обращаться к одному контроллеру игры. Для клиентов stdio нужен небольшой клиентский режим, который связывается с сервером лаунчера; его отключение не должно завершать общий сервер. Для HTTP требуется разграничение доступа участников, а не просто доверие к номеру стороны в аргументе.

## Что проверить до внедрения

1. Способ подключения модуля без неподтверждённого переписывания EXE: поддерживаемая точка расширения, если найдётся; иначе явно документированный, привязанный к сборке механизм загрузки.
2. Обработку штатных вкладок и события TCN_SELCHANGE. Простая вставка заголовка вкладки не создаёт работающую страницу и может нарушить индексную логику лаунчера.
3. Выполнение UI-операций в правильном потоке, размеры, DPI, локализацию, восстановление штатных обработчиков.
4. Совместимость обновлений: проверка сборки, безопасный отказ от подключения на неизвестной версии, отсутствие перезаписи пользовательских настроек.
5. Открытие/переключение/закрытие страницы, запуск игры, сворачивание и завершение лаунчера. После этого подключение реального MCP, а не кнопки, показывающие выдуманный статус.

На текущем этапе вкладка ещё не добавлена. Найдены и проверены окно, панель вкладок, конфигурация и архитектура бинарников.

## Дополнительный поиск исходников на GitHub

По просьбе пользователя повторно проверены GitHub repository/code search: `baratorch`, `HD_LauncherNative`, `HD5_Launcher`, `HD3_Launcher`, `HD_Launcher language:C++`, `IDC_BTN_HDEXE`, а также широкие запросы HoMM3/HD/launcher по README и описаниям.

- [baratorch/winpatcher_x86](https://github.com/baratorch/winpatcher_x86): публичный репозиторий профиля baratorch, есть `.cpp`, `.h`, `.sln`, `.vcxproj`. Описание — библиотека установки патчей и hooks. Это реальные исходники полезного компонента, но не UI лаунчера. Совпадение с установленным `patcher_x86.dll` не проверено.
- [Asmedian/heroes-launcher](https://github.com/Asmedian/heroes-launcher): текущий корень содержит `.gitattributes`, `.gitignore`, `HeroesLauncher.gif`, `README.md`; кода приложения нет. Это другой Heroes Launcher, не установленный HD Launcher.
- [AndreyKhrypach/HD3-Launcher-Fix](https://github.com/AndreyKhrypach/HD3-Launcher-Fix): README и готовый IPS-патч `_HD3_.dll` для конкретной старой версии. Не исходники лаунчера.
- Совпадения `IDC_BTN_HDEXE` ведут в переводы INI в ERA-Projects и языковых репозиториях, не в реализацию обработчиков UI.

Итог поиска: публичный исходный проект именно установленного HD Launcher не найден. Отрицательный результат поиска не доказывает отсутствие непроиндексированного или иначе названного репозитория. Заявлять, что найденный патчер позволяет пересобрать лаунчер, нельзя.
