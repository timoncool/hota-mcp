### Ранее зафиксированное падение карты (история)

Главная находка: кнопки подтверждения в модальных диалогах (`message:accept`, `message:confirm`, `turn:end`) доставлялись с subtype `0xd` и обработчик кнопки их молча игнорировал — вопрос закрывался, а действие не выполнялось. Обработчик кнопки (`h3hota HD.exe` `0x00455E70`) сообщает о нажатии только при subtype `0xa`; это учтено в native-мосте (`if(operation!=30)buttonMessage.subtype=0xa;`). После правки кнопки вопросов отрабатывают, игра не падает.

Также: постусловия действий теперь требуют смены `revision` (ложные `completed` при простом закрытии вопроса убраны); браузеры сохранения/загрузки распознаются структурно по `scnrsav.def`/`scnrlod.def`; добавлены dev-дамп диалога (`--ui`) и dev-ввод текста (`/bridge/text`).

Проверено живьём (игра PID 36792, наш сервер `build/session-load-v31`): вход/выход из города через `town:open:5`/`town:close` (adventure → town → adventure), чтение ресурсов/героя/города, распознавание браузера загрузки (`menu:load` → `menu:single`, заголовок «Загрузить игру», кнопки id186/id188). ### Ранее зафиксированное падение карты (история)

Игра падала при инициализации любой карты — `h3hota HD.exe+0xC7C34`, EXCEPTION_ACCESS_VIOLATION read 0x0000000D, стек всегда один (hota.dll+0xB05B2 → HD_HOTA.dll+0x17F4B0). Native-мост при этих падениях не подключён — `hota_game_bridge.dll` в стеке отсутствует. Адрес разобран статически:

```
0x004C7C16  mov  eax, [0x699538]        ; главный объект карты
0x004C7C10/2E  ecx = [main+0x1fc44]     ; ширина, [main+0x1fc40] → указатель массива тайлов, [main+0x1fc48] → z-глубина
0x004C7C2E  mov  ecx, [ecx + 0x1fc40]   ; ecx = 0
0x004C7C34  test byte ptr [ecx+eax*2+0xD], 0x10   <== чтение 0x0000000D
```

Это цикл обхода карты; указатель на массив тайлов нулевой. Совпадало с окном HotA «Обновить HotA до версии 1.8.1» при `HotA_Setup.ini` = 1.8.0. На текущий момент игра запускается и играется; смена настроек графики без просьбы пользователя недопустима (графика возвращена в исходное «32-bit OpenGL (resizable)»).

Пока это не вылечено, ни новая партия, ни загрузка сейва не проверяемы: любая карта валит игру. Следующий шаг — привести установку HotA/HD в согласованное состояние, затем повторить: браузер загрузки → выбрать сейв → «ЗАГРУЗИТЬ» → сверить ресурсы/героев/город.

Сейвы не удалять: `111ы.GM1` 119077 б, `111.GM1`/`AUTOSAVE.GM1` 117496 б, `BATTLE.GM1` 118979 б. ## Архитектура и эксперименты

- src/HotaMcp: reader, fairness checks, targets/routes, towns/actions, lazy session, журнал/план.
- native/launcher: x86 вкладка существующего лаунчера; эксперимент v4.
- native/game: x86 модуль, вызовы только на игровом UI-потоке, закрытый набор операций. Последний эксперимент build/v18. Параметр LPARAM: player low8, argument high bits. Контракт ещё нестабилен.
- DLL закрепляются до выхода процесса; build/vN нужны для разработки и НЕ являются финальной схемой установки.
- Диалоговые команды временно перехватывают callback/vtable экземпляра. Меню имеет отдельный callback, поэтому обобщение оказалось неверным. Вариант очереди меню тоже не признан рабочим. Требуется устранить выход/сбой и реентерабельность до нового игрового прогона.
- Игровые координаты/ресурсы напрямую не менялись. Записи модуля касались UI callback/event queue и обычного результата закрытия диалога.
- Старые MouseAsync/KeyAsync/InspectTile и Python-пробники пока остаются историческими; не использовать в продуктовом потоке. Удаление/изоляция — задача.
