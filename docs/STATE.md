## Архитектура и эксперименты

- src/HotaMcp: reader, fairness checks, targets/routes, towns/actions, lazy session, журнал/план.
- native/launcher: x86 вкладка существующего лаунчера; эксперимент v4.
- native/game: x86 модуль, вызовы только на игровом UI-потоке, закрытый набор операций. Последний эксперимент build/v18. Параметр LPARAM: player low8, argument high bits. Контракт ещё нестабилен.
- DLL закрепляются до выхода процесса; build/vN нужны для разработки и НЕ являются финальной схемой установки.
- Диалоговые команды временно перехватывают callback/vtable экземпляра. Меню имеет отдельный callback, поэтому обобщение оказалось неверным. Вариант очереди меню тоже не признан рабочим. Требуется устранить выход/сбой и реентерабельность до нового игрового прогона.
- Игровые координаты/ресурсы напрямую не менялись. Записи модуля касались UI callback/event queue и обычного результата закрытия диалога.
- Старые MouseAsync/KeyAsync/InspectTile и Python-пробники пока остаются историческими; не использовать в продуктовом потоке. Удаление/изоляция — задача.
