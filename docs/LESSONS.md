# Журнал уроков: что проверено, что сломано, что решено

Живой файл. Правило сессии 20.09.2026: каждое наблюдение, ошибка и вывод записывается сюда сразу, а не «потом». Свидетельством считается живой результат в игре или чтение структуры, а не догадка.

## 20.09.2026, сессия 3 (загрузка, бой, инструменты)

### Загрузка сохранения
- Крах `h3hota HD.exe+0x004C7C34` (read 0x0000000D) вызывала НЕ игра и НЕ установка HotA, а наш способ доставки нажатия: подмена vtable-обработчика кнопки `scnrlod.def`. Игра падала на инициализации карты.
- Рабочий путь — адресное оконное mouse-событие по границам, которые контрол сообщает сам (как в рабочем `save:confirm`). Зеркалирование дало успех: AUTOSAVE и `111ы` грузятся штатно, игра жива.
- Загрузку проверять различимым состоянием (дата, ресурсы, имя/позиция героя), а не «экран сменился»: загрузка той же партии выглядит как «ничего не произошло».
- Браузер сохранения/загрузки помнит последнюю папку; выход из него (`gspexit`/`scnrback`, id 188) теперь тоже адресное событие.

### Кнопки и вопросы
- Все кнопки диалогов (опции, браузеры, вопросы, боевая панель) — обычные контролы. Подмена vtable молча не срабатывает («Главное меню») или валит игру.
- Вопросы (Ok/Cancel, id 30725/30726, ассеты `iokay.def`/`icancel.def`) тоже адресные события. Фолбэки Enter/Escape убраны.
- Кнопка «Главное меню» из системных опций задаёт вопрос, но подтверждение возвращает в партию — ДЕФЕКТ, открыт.

### Выбор героя
- После экранов (город, бой, новый день) выделение героя теряется: `person+4 = -1`, наблюдение `hero = null`, `nearby` отвечает «Select a hero first».
- Инструмент `hero:select` (штатная клавиша H) добавлен и ОДИН РАЗ сработал (день 3, вернул Лабету), но позже не сработал (день 4, после отступления) — считать частичным, нужен надёжный путь (список героев/клик по герою на карте).
- Горячая клавиша H в H3 открывает список героев, а не «выбрать следующего» — вероятная причина.

### Бой
- `move_to` на отряд монстров НЕ останавливается рядом: герой входит в бой автоматически. Перед таким ходом нужно оценивать силы; в инструменте это надо разделить (подойти и атаковать — разные решения).
- Статы отряда без ПКМ: игра сама держит панель «Атк: 6(6)», «Зщт: 7(7)», «Урон: 2-4», «Здр: 20», «Дух:», «Удача:» рядом с активным/осмотренным стеком; это читается как обычные элементы боя. ПКМ-карточка показывает больше: атака, защита, урон, здоровье, текущее здоровье, скорость, способности (у гномов «20% шанс сопротивляться вражескому заклинанию»), количество «5/5».
- Наблюдение боя пока не публикует HP/урон/выстрелы — это пробел, из-за него бой ведётся вслепую.
- Боевая панель: id 2002 `icm002.def` — отступить (бегущий человек), id 2004 `icm004.def` — автобой (скрещённые мечи), id 2001 `icm001.def` — сдаться (недоступна против нейтралов), 2008/2009/2010 — книга/ждать/защита (ПРОВЕРИТЬ соответствие, кнопки могут быть смещены).
- Отступление проверено: `combat:retreat` → вопрос «Вы действительно хотите отступить?» → `message:confirm` → экран результата («Лабета трусливо бежит с поля боя») → `battle:accept` → карта. Герой выжил, армия потеряна, золото сохранилось.
- Урок партии: тридцать один троглодит был убит (победа, +165 опыта, потеряно 21 пикси и 3 воздушных элементаля), а 23 гнома (атака 6, защита 7, урон 2-4, здоровье 20) были бы смертельны: 460 HP против 170 и ~57 урона в раунд. Нападение без расчёта — ошибка игрока, не инструмента.

### Экономика и карта
- Таверна: найм героя 2500 золота, текст найма читается («Брисса, уровень 1, Элементалист»), подсказка таверны выдаёт место Грааля («Грааль можно найти на зелёной равнине»).
- За неделю город даёт прирост жилищ в первый день недели; доход начисляется в начале дня (проверено: +1000 золота в день на этой карте).
- Conflux (город Уоззар, id 5): рынок построен, гарнизон 20 пикси, жилища уровней 1-3 открыты, зал совета доступен.
- `move_to` в недостижимую цель: `uncertain` без движения и без смены даты — не ретраить, цель недостижима.

### Инструменты и инфраструктура
- HTTP-роуты моста НЕ отдают `bridge/map` и `bridge/target` (404) — доступно только MCP-клиенту. Для dev-проверок это неудобно, стоит выровнять.
- Перезапуск сервера на новой сборке: `build/restart-server.ps1 -LauncherPid <pid лаунчера> -Exe <новый exe> -WorkDir <репо>`.
- Память игры можно читать диагностикой: `HotaMcp.exe --diagnostic --read --address 0x... --length N --game-pid <pid>`. Проверено чтением персонажа: `person+0x9c` ресурсы (совпали с наблюдением), `person+4` = id выбранного героя (-1 = не выбран), `person+0x3e` = количество героев игрока.
- Скриншоты (`debug_snapshot`) — только костыль для разработки; боевая игра агента обязана идти по семантике.
