# Зачем этот playbook

Цикл «сохранил → вышел → загрузил» — обязательный минимум для продолжаемой партии. До 20.09.2026 загрузка на этой установке валила игру на инициализации карты (`h3hota HD.exe+0xC7C34`, read 0x0000000D). Причина была не в сейвах и не в установке HotA: сломанным был наш способ нажатия кнопки браузера. Ниже — работающая цепочка.

# Общий принцип кнопок

Все кнопки диалогов (браузеры, системные опции, вопросы) — обычные контролы диалога. Их нажимает **адресное оконное mouse-событие в границах, которые контрол сам сообщает** через структуры UI (адаптер считает координаты сам, агент картинку не размечает).

Проверено на этой машине: то же самое событие работает для кнопки сохранения (`scnrsav.def` id186), для кнопки загрузки (`scnrlod.def` id186), для «главное меню» (`somain.def` id108), для выхода из браузера (`gspexit.def`/`scnrback.def` id188) и для кнопок вопросов (`iokay.def` id30722/30725, `icancel.def` id30726).

Не использовать для этих кнопок подмену vtable и синтетические подтипы сообщений: для диалогов HD Mod доставка через хук не доходит до штатного результата. Симптомы: диалог закрывается, действие не выполняется (кнопка «главное меню»), либо игра падает при инициализации карты после «загрузки» (кнопка загрузки).

# Загрузка сохранения (рабочая цепочка)

1. Игра находится в главном меню: `observe` → `screen=main_menu`, доступны `menu:new`, `menu:load`.
2. `act(menu:load)` → `screen=game_type`; `act(menu:single)` → `screen=load_game` (заголовок «Загрузить игру»).
3. Прочитать `Saves`: `Entries[i]` = `{index, name, scenarioFile, folder, selected, x, y, width, height}`, плюс `SelectedIndex`. Строка-папка отличается отсутствием расширения `.GM1`; вложенные сейвы лежат внутри папки.
4. Если нужный сейв во вложенной папке: `act(load:open:<index папки>)` — игра входит в папку, список перечитывается (появляется строка `..` возврата).
5. `act(load:select:<index файла>)` — выбрать строку (одиночное адресное событие).
6. `act(load:confirm)` — кнопка «ЗАГРУЗИТЬ» (`scnrlod.def` id186) тем же адресным событием. Ожидаемый результат: `completed`, `screen=adventure`, игра жива.
7. Проверить загрузку по различимому состоянию, а не по «экран сменился»: `hero` (id/имя/позиция/армия), `date`, `resources`, `towns[].buildings`. Загрузка на этой машине мгновенная; если загружаешь то же состояние, что уже в партии, внешне не меняется ничего.

Свидетельство 20.09.2026: AUTOSAVE.GM1 (117 КБ, 19.09 21:06) загружен из главного меню; после загрузки `date=[1,1,1]`, `resources=[10,10,10,4,4,4,10000]`, `hero=139 Лабета (66,37)`, `movement=1630`, `mana=30`, армия `21/4/5` — совпадает с содержимым сейва, игра не упала.

# Что НЕ работает и почему

- Внутриигровой `game:load` (системные опции → кнопка «ЗАГРУЗИТЬ ИГРУ», отправляется `L`) открывает штатный вопрос «Вы уверены… несохранённые игры будут потеряны?». Подтверждение штатное, но отдельного браузера внутри партии не появляется: игра возвращается в партию. Проверено дважды (19.09 и 20.09). Для цикла «сохранил → загрузил» использовать путь через главное меню: либо перезапуск игры кнопкой Play лаунчера, либо кнопка «ГЛАВНОЕ МЕНЮ».
- «ГЛАВНОЕ МЕНЮ» (`somain.def` id108): адресное событие регистрируется, игра показывает вопрос подтверждения, отмена (`icancel.def`) возвращает в системные опции — то есть диалог работает. Но подтверждение (`iokay.def` id30725) возвращает в партию, а не в главное меню. Открытый дефект; для выхода в меню надёжнее перезапуск игры через Play.
- Хук-vtable доставка для кнопок браузера: сломана (см. выше). Не возвращаться к ней без нового разбора.
- Клавиатурный эксперимент `message:accept/confirm` через Enter и `decline` через Escape: снят. Вопросы надёжно отвечаются адресным событием по кнопке; Enter на вопросе главного меню закрывал диалог без выполнения действия.

# Сохранение

- `game:save` (системные опции, отправляется `S`) открывает браузер сохранения: `screen=save_game`, доступно `save:confirm` (кнопка `scnrsav.def` id186).
- Браузер помнит последнюю папку: открытый из партии, он показал содержимое `Games\Превосходство в воздухе` (`..`, `111`, `111ы`), а не корень.
- Перед подтверждением обязательно прочитать выбранную строку в `Saves`: подтверждение пишет в выбранное имя. В этой партии подтверждение без правки имени перезаписало бы `111.GM1`.
- Ввод имени файла и его чтение после ввода остаются незавершёнными (см. TASKS.md). Сейв `111ы.GM1` не перезаписывать.
- Игра сама пишет `AUTOSAVE.GM1` при смене суток (20.09 20:20 обновлён на дне 2) и `BATTLE.GM1` перед боем.

# Выход из браузера

- Браузер загрузки: кнопка `scnrback.def` id188 (семантическое `load:back` или адресное событие по элементу) → главное меню.
- Браузер сохранения: кнопка `gspexit.def` id188 (адресное событие по элементу) → назад в игру/опции.

# Мини-чеклист перед загрузкой

1. `observe` — revision свежий, `screen` ожидаемый.
2. Не подтверждать то, что не прочитано: имя строки, текст вопроса.
3. После действия `uncertain` — не повторять с новым operationId: сначала `observe`/`read_journal`.
4. После загрузки сверять позицию героя, дату, ресурсы и состав городов.
