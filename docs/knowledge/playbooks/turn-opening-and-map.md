# Контур решения

На начале хода агент получает новое согласованное `observe`, проверяет active player/phase/revision и разделяет: обязательный экран/диалог, активные герои, видимые цели, города и конец хода. Приоритеты и оценки — собственная адаптация агента; VCMI Nullkiller2 лишь подтверждает полезность разделения analyzer → goals → decomposition → execution.

Для карты допустим такой плановый цикл:

1. собрать собственные герои, движение, армию и только видимые цели;
2. сгруппировать цели по hero и по зависимости (например, объект, который блокирует другой объект);
3. отбрасывать stale target/revision и заново наблюдать;
4. выбрать одну короткую последовательность до следующей развилки;
5. выполнить только подтверждённые actions и после результата сделать новое наблюдение.

`nearby_targets` и `inspect_target` дают лишь текущую поддержанную часть видимых объектов и route data. Отсутствие route data не означает недостижимость. В текущем `GameTools.cs` нет `move_hero`, `select_hero`, `explore` или `end_turn`; их нельзя выдумывать.

## Разведка

Хранить можно то, что сторона уже законно увидела. Нельзя выдавать неоткрытые клетки, полную карту, чужой состав войска или скрытое состояние объекта. Если объект исчез из текущей видимости, ранее наблюдённая карточка помечается `last_seen`, а не обновляется скрытым значением.

## Источник алгоритма и адаптация

Из VCMI перенесена только форма цикла и идея ObjectClusterizer/DeepDecomposer. LLM-адаптация должна сама выбирать цель по ID и запрашивать действие через capability discovery. Правила местности, path cost и полезность маршрута приходят из отдельной справки или текущего разрешённого наблюдения; мост не подмешивает совет.
