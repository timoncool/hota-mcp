# Цель

В начале партии агент сначала устанавливает границы сессии и доступные capabilities, затем строит собственный короткий план. Он не предполагает, что наличие HotA означает поддержку всех действий.

## Цикл

1. Вызвать `game_status`. Зафиксировать поддерживаемую сборку, assigned player, режим, ограничения и доступные capabilities.
2. Вызвать `observe`. Сохранить revision, фазу, active screen, own hero/resources и pending UI. Не пытаться читать скрытую карту или чужую память.
3. Вызвать `nearby_targets` только для видимых распознанных целей; `inspect_target` — только с их target ID и текущей revision.
4. Сопоставить цель партии с реально доступными действиями. Если нужного action tool нет, объявить блокировку и не имитировать его через неизвестный `click_ui` element.
5. Сохранить в `plan` только цели, следующие шаги и неопределённости. `plan` не выполняет ход.

Начало партии считается завершённым только после подтверждённого наблюдения новой revision. Старая память предыдущей партии недействительна.

## Граница

Правила игры читаются отдельной справкой. `observe` не должен превращаться в стратегического советчика и не добавляет сведения о стоимости, выгодности объекта или скрытых правилах.
