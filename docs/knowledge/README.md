# Корпус знаний агента (docs/knowledge)

Единственное место, где лежат знания об игре. Агент читает его не глазами, а через мост:
`hota_docs` задаёт вопрос словами, `hota_docs_catalog` показывает, что вообще есть,
`hota_docs_read` открывает раздел целиком. Ничего отсюда не подмешивается в наблюдения.

Машинный индекс — [llms.txt](llms.txt), весь корпус одним файлом — [llms-full.txt](llms-full.txt),
оглавление каждой ветки — `README.md` внутри неё. Всё это собирает `python build/gen-docs-nav.py`,
руками не правится.

## Шесть веток по назначению, а не по происхождению

| Ветка | На какой вопрос отвечает |
| --- | --- |
| [agent/](agent/README.md) | **как играть через мост**: с чего начать, какие экраны он знает и чем из каждого выйти, какие есть инструменты, пошаговые сценарии хода, города, боя, сохранения |
| [rules/](rules/README.md) | **как игра считает**: формула урона, стоимость шага, экономика города, навыки и магия, скрытые числа повышения уровня, охрана банков, события и квесты карты, найм и дипломатия, ростеры трёх фракций HotA |
| [play/](play/README.md) | **как решать**: проходим ли бой, в каком порядке строить, игровые циклы, приоритеты по неделям, реестр ситуаций |
| [official/](official/README.md) | **первоисточники как есть**: мануал 1999 года, русская справка из установки игры, официальная документация HotA |
| [engine/](engine/README.md) | адреса и структуры настоящего `h3hota HD.exe`, на которые опирается мост |
| [sources/](sources/README.md) | откуда что взято и разбор опубликованных алгоритмов игровых ботов |

Правило разделения: `rules/` отвечает числом, `play/` — решением. Если нужен ответ «сколько», это
`rules/`; если «стоит ли», это `play/`.

## Карточки правил из самой игры

Отдельно от этих файлов мост читает 17 таблиц установленной игры (`SSTRAITS`, `SPTRAITS`,
`CRTRAITS`, `artraits`, `HOTRAITS`, `HeroSpec`, `Building`, `BldgNeut`, `BldgSpec`, `Dwelling`,
`ObjNames`, `MineName`, `TERRNAME`, `PriSkill`, `SkillLev`, `CrBanks`, `TownType`) и отвечает по ним
инструментом `hota_reference`: карточка существа, заклинания, навыка, артефакта, здания, героя,
объекта карты, шахты, местности или фракции — ровно той версии, в которую идёт партия.

Важная граница: **существ, героев и построек трёх фракций HotA в этих таблицах нет** — `CRTRAITS`
в архиве HotA это тот же файл, что в базовой игре. Их описания лежат в официальной документации
HotA по-английски, а русско-английский мост имён — в [rules/hota-rosters.md](rules/hota-rosters.md).

Карточки и проза не конкурируют в одной выдаче: `hota_docs` ищет по прозе и подключает карточки,
только если проза молчит.

## Как устроен поиск

SQLite FTS5 в памяти: `bm25()` ранжирует, `snippet()` вырезает отвечающий кусок. Русские окончания
сводятся к основе в отдельной копии каждого поля, поэтому «логистике» находит «логистика», а в
ответе виден настоящий текст. Сначала спрашивается конъюнкция всех слов запроса, и только потом
дизъюнкция — так секция, покрывающая весь вопрос, обходит ту, что делит с ним одно слово. Опечатки
и ослышки ловит триграммный индекс по заголовкам.

Выдача трёхуровневая: `titles` — только файл и заголовок, `snippet` (по умолчанию) — отвечающий
абзац, `full` — раздел целиком. Длинное `hota_docs_read` отдаёт окнами и всегда говорит, с какого
места продолжать; молча ничего не обрезается.

Подробности решения и замеры — [DESIGN.md](DESIGN.md).

## Правила корпуса

1. Единый формат шапки: YAML с полями `id`, `title`, `game_version_scope`, `topics`,
   `verification_status`, `type`, `layer`, `updated`.
2. Каждый раздел заканчивается строкой `Источник:`.
3. Каждый файл заканчивается разделом `## Пробелы` — чего в нём заведомо нет. Агент обязан знать
   границу своего знания, а не додумывать.
4. Один факт — один хозяин. Повтор заменяется ссылкой на хозяина, а не копией.
5. Ссылки внутри корпуса — относительные. Абсолютных путей конкретной машины быть не должно.
6. Рабочие документы разработки (`docs/STATE.md`, `docs/TASKS.md`, `docs/LESSONS.md`,
   `docs/HANDOFF-*.md`) — не знания об игре и в корпус не входят.

## Чего в корпусе нет

Пробелы перечислены пофайлово. Самое существенное на 21.09.2026:

- Числовых характеристик существ трёх фракций HotA нет ни в таблицах игры, ни сводной таблицей в
  корпусе — только текстовые описания способностей в официальной документации.
- Порядок построек день-в-день для Причала и Фабрики не найден в проверяемых источниках.
- Официального числового порога «во сколько раз надо быть сильнее для безопасного боя» не
  существует: источники прямо это подтверждают.
- Экран осады и экран сдачи мостом не проверены.
